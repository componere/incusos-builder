# Implementation plan

## Recommended end state

Keep the existing Release Please → draft GitHub Release → tag-triggered build/attestation → human publication lifecycle. Produce five native archives (`darwin/{amd64,arm64}`, `linux/{amd64,arm64}`, `windows/amd64`), a checksummed and attested `install.sh`, an in-repository Nix flake, and post-publication Homebrew/Scoop metadata. Homebrew and Scoop metadata must not be committed until the GitHub Release is public.

The expected first public release with the new contract is **v0.2.0** under the current pre-1.0 Release Please policy. If intervening changes cause Release Please to choose a later version, apply the same gate to that version. Leave the existing unpublished v0.1.0 draft untouched.

## Decisions to settle before coding

### 1. Draft-release timing: preserve the human gate; publish channels after `release.published`

**Recommendation — no additional confirmation needed:** retain the deliberate human publication gate in `.github/workflows/release.yml` and `.github/workflows/release-please.yml`. During the tag run, generate the Homebrew formula and Scoop manifest with `skip_upload: true` and retain the exact generated files as a named Actions artifact. Add `.github/workflows/publish-channels.yml`, triggered by `release: types: [published]` with a manual retry input, to retrieve that artifact, validate it against the now-public release, exercise the public installer, and only then update the tap and bucket. The in-repo Nix flake builds from source and does not point at draft release assets, so it is not subject to this timing problem. `install.sh` may be attached to the draft, but `releases/latest/download/install.sh` is documented as usable only after publication.

GoReleaser v2.17.1 source establishes the mechanics: `release.disable: true` disables only the release client, not `brews`, `scoops`, or `nix`; global `--skip=publish` suppresses those publisher pipes. With `release.disable: true`, every configured publisher needs the explicit template below because `.ReleaseURL` is unavailable:

```yaml
url_template: "https://github.com/componere/incusos-builder/releases/download/{{ .Tag }}/{{ .ArtifactName }}"
```

A second `goreleaser release --clean` after publication, without `--skip=publish`, would publish brew/scoop/nix while leaving the GitHub Release alone if each publisher had that template. It would also rebuild the binaries; it would therefore need to download the public `checksums.txt`, compare every recomputed archive digest, and fail closed before publishing. Do **not** choose that path: passing the exact formula and manifest generated by the original tag build removes the rebuild-determinism question. Publishing metadata before the release is public and accepting a broken-URL window is rejected.

### 2. Homebrew: formula only

**Recommendation — no confirmation needed:** publish only `Formula/incusos-builder.rb` in `componere/homebrew-tap`; do not add a cask. `brews:` has emitted a deprecation notice since GoReleaser v2.10, but formulas support both Linux and macOS, while the replacement `homebrew_casks:` surface is macOS-only and does not meet this CLI’s Linux requirement. Pin the release workflows to the tested GoReleaser v2.17.1 release, run `goreleaser check` and `healthcheck` in the first spike, and record whether the deprecation is a warning or changes the exit status. The tap layout is `Formula/.gitkeep` initially and `Formula/incusos-builder.rb` after the first channel update; there is no `Casks/` directory.

### 3. Windows: use the existing injection seam, then require native behavior tests

**Recommendation — no confirmation needed because Scoop is an accepted goal:** keep the free-space adapter in `internal/update` rather than introducing a new port package. `assetCache.freeBytes func(string) (uint64, error)` in `internal/update/cache.go` is already the A1 test seam. Move the Unix syscall implementation out of `cache.go`, limit it to Darwin/Linux, and add `internal/update/space_windows.go` using `golang.org/x/sys/windows.GetDiskFreeSpaceEx`; `x/sys` is already direct. This is a small platform adapter inside the package that owns the cache, consistent with A1/A3, rather than a second abstraction beside the existing injected function.

Use both gates: a fast `GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build` in the normal Moon check and a required `windows-latest` CI job that runs `go test ./...`, builds the real `.exe`, and runs `incusos-builder.exe --version`. The native test suite exercises config/cache paths and real go-diskfs ISO/raw creation/read-back (`internal/media/rescue_test.go`), so Scoop must not be advertised until it passes. A live multi-GiB update download is not appropriate for every PR; after the native suite passes, document the precise support boundary as Windows AMD64 rather than labeling the channel experimental. If the native media tests cannot pass, keep the Scoop manifest unpublished and omit Scoop from user docs until fixed.

### 4. Archive migration: keep a slim, renamed final-asset validator

**Recommendation — no confirmation needed:** replace raw binaries with `.tar.gz` archives on Darwin/Linux and a `.zip` on Windows AMD64. Generate SBOMs for the shipped archives rather than for hidden intermediate binaries. Retain the valuable half of `.github/scripts/stage_ghd_release_assets.py` as `.github/scripts/stage_release_assets.py`: remove TOML/`ghd` validation, but keep exact asset-set validation, archive-member checks, checksum parsing, checksum coverage/digest verification, and final staging. Rename and wire its unittest into Moon/CI; the current unittest is not called by CI.

The archive PR’s intermediate contract is five archives + five archive SBOMs + `checksums.txt` (11 assets). The installer PR extends the final contract to 12 by adding `install.sh`. Both production and dry-run smoke tests must extract the host archive to a private temporary directory before executing it; the Windows ZIP must be inspected for a root `incusos-builder.exe`. `gh release upload dist/release-assets/*` remains format-neutral. `checksums.txt` remains the isolated `attest.yml` subject, but its entries change from raw binaries to the final published files.

### 5. Nix: in-repository source flake

**Recommendation — no pre-start confirmation needed because it is the reversible, no-extra-infrastructure choice:** add `flake.nix` and `flake.lock` to `componere/incusos-builder` using `buildGoModule`. This matches the request’s explicit creation of only a tap and Scoop repository, gives users `nix run github:componere/incusos-builder#incusos-builder`, and requires no third cross-repo credential. Do not add a GoReleaser `nix:` block. A separate `componere/nix` NUR-style binary repository remains a deferred option if maintainers later prefer installing the exact attested archives.

Own the costs explicitly. Set `doCheck = false` in the derivation because required CI already runs `moon run root:test`; Nix’s default check phase would duplicate subprocess/testscript and fixture-generating tests in a networkless sandbox on every Nix build. The required Nix job still proves the package builds and runs. Set `CGO_ENABLED=0`, `subPackages = [ "cmd/incusos-builder" ]`, and the same `-X main.version=${version}` stamp used by GoReleaser/melange. Put `# x-release-please-version` on the literal version and add `flake.nix` as a generic `extra-files` entry in `release-please-config.json`. The Nix output is a source-built, byte-distinct binary and is **not** covered by the release archive attestation; docs must say that.

For every effective `go.mod`/`go.sum` change, refresh `vendorHash` by setting it to `lib.fakeHash`, running `nix build .#incusos-builder`, copying the reported `got: sha256-…` value into `vendorHash`, and rerunning `nix flake check --all-systems --no-build` plus `nix build`. Do not commit `vendor/`. A required `Nix` status must run those commands on every PR; a stale hash must fail before merge, including Dependabot batches.

### 6. `install.sh`: checksum always, optional GitHub attestation, no Cosign mode

**Recommendation — no confirmation needed:** keep the first script reviewable. Support only `--version latest|vX.Y.Z`, `--install-dir DIR`, `--verify checksum|gh`, `--allow-root`, and `--help`, with environment counterparts for version, install directory, and verification mode. Default to `checksum`; `--verify gh` additionally requires an installed/authenticated `gh` and runs `gh attestation verify` against `componere/incusos-builder/.github/workflows/attest.yml` and the exact tag. Do not add `auto`, `--dry-run`, `--quiet`, profile editing, or `sudo`.

Do not add `--verify cosign`: the repository does not sign `checksums.txt`; Cosign currently signs only the OCI image. The script must never document or attempt verification of a nonexistent bundle. Track `install.sh` at the repository root and upload the unchanged file as a release asset. Configure `checksum.extra_files: [{ glob: ./install.sh }]`; GoReleaser hashes that pre-existing file but does not add it to the upload artifact list, so `stage_release_assets.py` must copy it explicitly. The POSIX script uses `set -eu`, a private temp directory, HTTPS-only downloads, curl/wget fallback, SHA-256 via `sha256sum`/`shasum`/OpenSSL, exact archive-member extraction, a pre-install `--version` smoke test, same-filesystem staging/rename, root refusal unless explicitly overridden, no prompts, and `main "$@"` as its final line. Present download → verify/inspect → execute as the hardened path; label `curl | sh` as a transport-trust convenience.

### 7. Repositories and credentials

**Recommendation — developer confirmation and human action required before the channel-publishing PR merges:** create public, non-template `componere/homebrew-tap` and `componere/scoop-bucket`, both with default branch `main`. Initialize the tap with `Formula/.gitkeep` containing `# This directory is populated by release automation.` and the bucket with a root `.gitkeep`; generated outputs are `Formula/incusos-builder.rb` and root `incusos-builder.json`. Match the Meigma pattern: no workflows or rulesets in these two generated-metadata repositories, because release automation commits directly to `main`. Adding protection later requires an explicit publisher bypass.

Use two independent fine-grained PATs as the least-surprising implementation of the required secret contract: `HOMEBREW_TAP_TOKEN`, restricted to `componere/homebrew-tap` with **Contents: read and write**, and `SCOOP_BUCKET_TOKEN`, restricted to `componere/scoop-bucket` with the same permission. Neither needs Actions, Administration, or Workflows permission. A GitHub App installation token is preferable operationally if the developer wants to change the secret contract; confirm that choice before workflow code is finalized because it requires storing App credentials and minting short-lived tokens rather than storing these two token secrets. There is no Nix token in the recommended design. Store the source credentials in 1Password’s `Development` vault, preferably a dedicated `componere-install-publishers` item rather than mixing them into `componere-release-please`, then copy them into the two named repository secrets. Repository creation and token minting are human prerequisites, not agent tasks.

## What can be built before the new repositories/tokens exist

Everything except the actual target-repository commits: Windows support/tests; archive migration; ghd deletion; the Nix flake; installer/static/behavior tests; GoReleaser formula/Scoop generation with `skip_upload: true`; `dist/` inspection; staging/checksum validation; manual `Release Dry Run`; docs drafts. No secret should be present in PR or dry-run jobs. The only blocked work is end-to-end `release.published` credential validation and the first writes to `Formula/incusos-builder.rb`/`incusos-builder.json`.

## Verification strategy without cutting a release

- `moon run root:check` proves Go/unit tests, Windows cross-compile, staging tests, installer static/behavior tests, and strict docs.
- Required `Windows` proves native Windows execution and diskfs-backed media tests.
- Required `Nix` proves all-system evaluation plus one native source build/run and fails on stale `vendorHash`.
- `goreleaser check`, `healthcheck`, and the synthetic release prove schema/tool availability and expose the formula deprecation behavior.
- A manual `Release Dry Run` on each release-related PR is mandatory because its expensive jobs deliberately report `skipping` on ordinary PRs. It additionally rehearses the five archive/SBOM set, archive extraction, Windows ZIP inspection, `install.sh` staging/checksum/tamper behavior, formula generation, Scoop generation, and the existing melange/apko build.
- `workflow_dispatch` proves generation and validation but intentionally cannot prove public URLs, release events, target credentials, package-manager installs, GitHub immutable state, or post-publication writes. Those are v0.2.0 gates, not claims made from a green dry run.

## Risk register

| Risk | Mitigation |
|---|---|
| Draft assets 404 while metadata is public | Never publish formula/manifest before `release.published`; validate public URLs before target commits. Nix builds source and is independent. |
| Metadata artifact expires during a long human review | Retain 90 days; if expired, rerun the still-draft release workflow before publication. Fail after publication rather than rebuilding without checksum comparison. |
| Windows compiles but media behavior fails | Require native `go test ./...`, real diskfs fixture creation/read-back, executable smoke, and no Scoop docs/publication until green. |
| In-repo `vendorHash` goes stale after Dependabot | Exact fakeHash refresh procedure; required `Nix` status on every PR; no optional/advisory Nix job. |
| Nix users assume release provenance | Trust-model/how-to text says `buildGoModule` output is source-built and not the attested GoReleaser archive. |
| Cross-repo PAT expires or is revoked | One repo-scoped PAT per target, 1Password source record/expiry, idempotent manual retry, and visible post-publish failure. Prefer App tokens later if the credential contract is deliberately changed. |
| `brews:` deprecation becomes removal | Formula-only rationale, exact v2.17.1 pin, check/healthcheck spike, generated-formula fixture; migrate to a manual formula generator before moving to a GoReleaser version that removes it. Do not substitute a macOS-only cask. |
| Immutable releases reject re-uploaded assets | All `--clobber` uploads occur while draft; resolver refuses a public release; post-publish workflow never edits release assets. |
| v0.1.0 draft predates the new contract | Leave it unpublished and untouched. Do not publish or re-release it. Its raw binary names cannot satisfy new archive URLs, formula, Scoop, or installer. Document channels as v0.2.0+. |
| Partial Homebrew/Scoop update | Independent idempotent jobs; retry compares current contents and completes only the missing target. Metadata always references already-public assets. |
| `curl | sh` truncation or transport compromise | Hardened docs prefer download/check/inspect/execute; EOF `main`; no sudo/profile edits; checksum mandatory; optional exact-workflow GitHub attestation. |
| GoReleaser output naming changes | Pin v2.17.1, freeze observed `dist/artifacts.json` contract in a single staging validator and unittest, rehearse production command in dry run. |
| Release event or Actions artifact lookup fails | Manual tag retry on `Publish Channels`; exact tag-qualified artifact name; fail on zero/multiple/expired matches. |

## Explicit non-goals

- Do not auto-publish the GitHub draft or remove the human gate.
- Do not publish, recreate, mutate, or “upgrade” the existing v0.1.0 draft.
- Do not make the same ghd/archive change in `meigma/template-go` or `template-go-api` in this effort; record it as upstream follow-up only.
- Do not add `componere/nix`, community NUR, or nixpkgs publication now. The separate binary NUR remains a reversible future enhancement.
- Do not add Winget, Chocolatey, nfpm, AUR, deb/rpm, Docker `latest`, or Windows ARM64.
- Do not add Cosign signing for `checksums.txt` or claim `--verify cosign`; container Cosign signing remains unchanged.
- Do not change the isolated `attest.yml` signer identity or collapse it into the build workflow.
- Do not redesign the container melange/apko pipeline while changing native archives.
- Do not add sudo, shell-profile editing, prompts, telemetry, automatic updater behavior, or a dedicated installer domain.
- Do not turn the live multi-GiB Windows update campaign into an ordinary PR test; use the native deterministic media suite as the Scoop gate.
