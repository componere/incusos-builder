# Technical Notes

- Use hexagonal architecture at all times. Keep business logic isolated from CLI, filesystem, network, storage, and other external adapters.
- Prefer functional testing before calling any feature complete. Unit tests are useful, but they do not prove the tool works the way the design intends.
- Take an agile approach to development. Avoid waterfall: underspecify when useful, prototype early, learn from the result, and refine from working behavior.
- Authoritative design docs: `.journal/001/ARCHITECTURE.md` (hexagonal design, ports, exit taxonomy, invariants) and `.journal/001/PLAN.md` (7-phase implementation plan). Phases 0–6 are merged (PRs #7–#9, #11–#13, #19). v0.1.0 was tagged and built on 2026-08-17 (PR #10); its artifacts are signed, attested, and consumer-verified, but the GitHub Release is still a **draft** awaiting manual publication.

- Seeding mechanic confirmed live: seed-data partition starts at exactly byte 2,148,532,224 (both arches), 100 MiB; uncompressed tar, entries mode 0600, yaml/v4 `WithV2Defaults()` byte-matches upstream `writeSeed`. GPT probed per-image (512/2048/4096 sector sizes; ISO layout puts the header at byte 2048).
- Sentinels live in `internal/errdefs` (leaf) with §6-named re-exports (`update.ErrFetch`, `config.ErrConfig`, …); exit taxonomy 0/1/2/3/4/5/6 mapped only in `internal/cli`.
- Server documents (index.json, update.json, sjson payload) are plain-decoded by design; integrity = digests + caps (64 MiB index / 1 MiB metadata) + three-way Filename/Sha256/Size binding. Plain `http://` `--server` is a usage error; the HTTPS client also rejects redirect downgrades on the final response URL.
- Rescue media: go-diskfs v1.9.4, RR-only ISO (go-diskfs Joliet output unusable), GPT+FAT32 raw at 1 MiB with proportional FAT-overhead sizing; `WriteRescue` replaces the tmpPath inode — publishers must reopen by path. go-diskfs FAT `File.Read` can return final-cluster zero slack to `io.ReadAll`; read exact logical bytes with `Stat` + `io.ReadFull`.
- Boot acceptance: **passed** 2026-08-17 on Semaphore Cloud (`f1-standard-4`, nested KVM, Incus VM with UEFI + vTPM), pipeline `4c5cc805` / job `a8b16331`, ~$0.25. Seed consumption was observed for the first time anywhere. O1–O3 were asserted against strings in the pinned upstream source; O4 (recovery payload) was accepted by the pipeline and adjudicated by the developer, because the guide forbids inventing a success criterion. Record `.journal/005/BOOT_10_RECORD.md`, raw log `.journal/005/TRACK_C_GATE_LOG.txt`, runbook `.journal/005/TRACK_C_RUNBOOK.md`. The Phase 5 mystery is solved twice over: the old gate hashed the **source** installer media, which `CleanupPostInstall` never modifies, so it could not pass on any host at any price; and plain QEMU has no `org.linuxcontainers.incus` virtio port, so the installer TUI never mirrored to `ttyS0` and a failed install looked identical to a silent one (`internal/tui/tui.go:67-71`). Still untested: `N-MEDIA-3`, the NUL-padded ISO label — the raw config matches the GPT partlabel and never reads it.
- E2E: `root:e2e` is opt-in (`INCUSOS_BUILDER_E2E=1`, `runInCI: false`) and live-proves versions parsing, smallest-image build, eleven-section seed round-trip, and exact ISO/FAT32 rescue read-back. `internal/testfixture.Generate` makes a sparse ~2.7 MB mirror for ordinary testscript coverage of exit codes 2–6, `--json`, `-o -`, and SOPS stdin. Stream large artifacts; never capture them in test memory.
- SOPS: any top-level `sops` key selects in-memory decryption; all decrypt failures map to exit 4. Throwaway age key + fixtures under `internal/config/testdata/`.
- Tooling gotchas: run lint via `mise x -- golangci-lint` (a global 2.11.4 shadows the pinned 2.12.2); moon caches can mask stale lint results; agent contexts should demand cwd verification (worktree, not main checkout) and rebuilding a package after every file write. Removing a Worktrunk worktree leaves a stale golangci-lint cache that fails the next `root:lint` from a fresh worktree with `can't read file … no such file`; `golangci-lint cache clean` clears it. This recurred three times in one session, so treat it as expected rather than a new defect.
- Release plumbing: Release Please uses `COMPONERE_RELEASE_APP_CLIENT_ID` (repo var) + `COMPONERE_RELEASE_APP_PRIVATE_KEY` (secret) from 1Password `Development/componere-release-please`; bypass slug `componere-release-please`. `release.yml` creates the GitHub Release as a **draft** for manual inspection, but the container image is public the moment it is pushed — GHCR has no draft state, so those two artifacts go live at different times. Only `release.yml` calls `attest.yml`; the dry run merely asserts the file exists, so attestation changes cannot be exercised before a real release.
- Release versioning: the manifest seeded `0.1.1` from `meigma/template-go` — the template's own release state, not ours — which made Release Please propose `0.1.2` from releases that never happened. Corrected in PR #26. Two non-obvious mechanics, both read from release-please source: `manifest.ts` excludes exactly `"0.0.0"` from the manifest backfill, so a `0.0.0` manifest means *no previous release* and `base.ts buildNewVersion()` returns `initialReleaseVersion()` — which defaults to **1.0.0** unless `initial-version` is set; and `bump-patch-for-minor-pre-major` makes features bump the patch below 1.0, which would have frozen the project at 0.1.x forever. Current config: manifest `0.0.0`, `initial-version: "0.1.0"`, `bump-minor-pre-major: true` (breaking → minor, stays in 0.x), `bump-patch-for-minor-pre-major: false`. `CHANGELOG.md` must stay **empty**, not a `# Changelog` stub: the updater runs `adjustHeaders()` over pre-existing content when no version heading exists and re-appends the demoted stub as a stray `## Changelog` (PR #29).
- Verifying releases: `gh` 2.97.0 prints **nothing** on a successful `gh attestation verify`, so a bare exit 0 is not evidence. Pair every check with a deliberate falsifier — a wrong `--source-ref` or a foreign `--certificate-identity-regexp` — and read the failure text, which names the real attested ref and signing identities (`attest.yml@refs/tags/v0.1.0` and `release.yml@refs/tags/v0.1.0`).
