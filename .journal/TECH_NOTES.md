# Technical Notes

- Use hexagonal architecture at all times. Keep business logic isolated from CLI, filesystem, network, storage, and other external adapters.
- Prefer functional testing before calling any feature complete. Unit tests are useful, but they do not prove the tool works the way the design intends.
- Take an agile approach to development. Avoid waterfall: underspecify when useful, prototype early, learn from the result, and refine from working behavior.
- Authoritative design docs: `.journal/001/ARCHITECTURE.md` (hexagonal design, ports, exit taxonomy, invariants) and `.journal/001/PLAN.md` (7-phase implementation plan). Phases 0–5 are merged (PRs #7–#9, #11–#13); only Phase 6 (docs/release/v1) remains.
- Upstream pin: `github.com/lxc/incus-os/incus-osd@v0.0.0-20260815030500-0f5b8057f2fc` (commit; the release tag lacks `api/seed.Services`). `--version` prints it via `runtime/debug.ReadBuildInfo`. CI gate `root:check-upstream` denies `incus-osd/{internal,cmd}` in the closure.
- Upstream reference: shallow clone of `lxc/incus-os` at `reference/incus-os/` (gitignored). Spike findings live on master under `docs/notes/spike-1*.md`; spike code quarantined under `spikes/` (own go.mod each, never promoted).
- Seeding mechanic confirmed live: seed-data partition starts at exactly byte 2,148,532,224 (both arches), 100 MiB; uncompressed tar, entries mode 0600, yaml/v4 `WithV2Defaults()` byte-matches upstream `writeSeed`. GPT probed per-image (512/2048/4096 sector sizes; ISO layout puts the header at byte 2048).
- Sentinels live in `internal/errdefs` (leaf) with §6-named re-exports (`update.ErrFetch`, `config.ErrConfig`, …); exit taxonomy 0/1/2/3/4/5/6 mapped only in `internal/cli`.
- Server documents (index.json, update.json, sjson payload) are plain-decoded by design; integrity = digests + caps (64 MiB index / 1 MiB metadata) + three-way Filename/Sha256/Size binding. Plain `http://` `--server` is a usage error; the HTTPS client also rejects redirect downgrades on the final response URL.
- Rescue media: go-diskfs v1.9.4, RR-only ISO (go-diskfs Joliet output unusable), GPT+FAT32 raw at 1 MiB with proportional FAT-overhead sizing; `WriteRescue` replaces the tmpPath inode — publishers must reopen by path. go-diskfs FAT `File.Read` can return final-cluster zero slack to `io.ReadAll`; read exact logical bytes with `Stat` + `io.ReadFull`.
- Boot gate: the Phase 5 Linux QEMU+swtpm+Secure-Boot run enrolled keys but observed no target-disk writes, so seed consumption and recovery acceptance remain unproven. A CI gate is not viable; run `docs/docs/how-to/verify-boot-acceptance.md` before every release tag until one succeeds. Evidence: `docs/notes/phase-5-boot-{probe.md,evidence.json}` and Actions run 31958439711.
- E2E: `root:e2e` is opt-in (`INCUSOS_BUILDER_E2E=1`, `runInCI: false`) and live-proves versions parsing, smallest-image build, eleven-section seed round-trip, and exact ISO/FAT32 rescue read-back. `internal/testfixture.Generate` makes a sparse ~2.7 MB mirror for ordinary testscript coverage of exit codes 2–6, `--json`, `-o -`, and SOPS stdin. Stream large artifacts; never capture them in test memory.
- SOPS: any top-level `sops` key selects in-memory decryption; all decrypt failures map to exit 4. Throwaway age key + fixtures under `internal/config/testdata/`.
- Tooling gotchas: run lint via `mise x -- golangci-lint` (a global 2.11.4 shadows the pinned 2.12.2); moon caches can mask stale lint results; agent contexts should demand cwd verification (worktree, not main checkout) and rebuilding a package after every file write.
- Release plumbing: Release Please uses `COMPONERE_RELEASE_APP_ID` (repo var) + `COMPONERE_RELEASE_APP_PRIVATE_KEY` (secret) from 1Password `Development/componere-release-please`; bypass slug `componere-release-please`. `create-github-app-token` deprecates `app-id` → switch to `client-id` (in the op item) when next touching the workflow.
